# P0（V0）方案：多模块骨架与短链核心迁移

> 本文是 P0 阶段的方案文档（事后入库，便于复盘）。
> 对应版本：V0 ｜ 状态：✅ 已完成（2026-10-15）｜ 执行记录见 `docs/devlog/V0-P0-多模块骨架与核心迁移.md`

---

## 1. 目标

在 AAF-link-platform 搭建 Maven 多模块骨架（parent + common/gateway/auth/core/stats），把 AAE-short-link 的短链核心代码迁移到 link-core，保证编译与原有单测通过。

## 2. 核心策略：三个安全点

不是"先测试还是先改 import"二选一，而是按顺序走三步，**一次只引入一个变量**：

1. **安全点一**：先在 AAE 原仓库 `mvn clean test` 拿基线 → 否则后面变红无法判断是谁弄坏的
2. **安全点二**：原样复制到 link-core（**一行 import 不改**）→ 再跑一次 → 证明"复制无损"
3. **安全点三**：抽公共类、改 import → 每改一批跑一次

任何一次变红都能立刻定位：第 2 步红 = 搬目录问题；第 3 步红 = 改 import 问题。

## 3. 关键决策

| # | 决策 | 理由 |
|---|---|---|
| D1 | link-core 包名保留 `com.shortlink.*` | 涉及 100 个文件，重命名 diff 大到无法二分定位；规范化留到 V1 做 |
| D2 | 统计代码留 link-core | `RedirectServiceImpl` 依赖 `VisitRecorder`，硬抽会产生循环依赖；P5 再抽 |
| D3 | Boot 3.2.5 + Cloud 2023.0.3 + SCA 2023.0.3.2 | 不改 AAE 的 Boot 版本，迁移只引入"模块化"一个变量 |
| D4 | 骨架模块仅编译通过 | P0 硬指标是"编译 + 198 单测"，未接 Nacos 时要求可启动是假失败 |
| D5 | **复制而非移动** | AAE 要原样保留，作为 P7 压测对比基线与面试演进故事本体 |
| D6 | 端口 gateway 8080 / auth 8081 / core 8082 / stats 8083 | AAE 已占 8080 |
| D7 | 依赖方向 `common ← core/gateway/auth/stats` 单向 | 保证后续服务可复用 common 而不污染 core |
| D8 | 环境隔离：新库 `link_platform` + Redis db 1 + MQ 拓扑名 `link.visit.*` | 两个项目要能同时跑；P4 加 tenant_id 不能污染 AAE 基线 |

## 4. 公共类抽取边界（有意的取舍）

- **搬入 common**：`Result`、`BizException`、`DegradedException`、`GlobalExceptionHandler` + 新增 `TenantContext`、`CommonConstants`
- **留在 core**：`ClientIpResolver`（依赖 `jakarta.servlet`，WebFlux 网关用不了）、`RefererParser`/`UserAgentParser`（只被统计链路用）、`ratelimit` 两个类
- **`DegradedException` 必须联动搬**：`GlobalExceptionHandler` 引用了它，只搬 handler 会造成 `common → core` 反向依赖

## 5. 验收结果（实际数据）

| 项 | 结果 |
|---|---|
| AAE 基线 | `Tests run: 198, Failures: 0, Errors: 0, Skipped: 1` |
| 复制后 | 198 / 0 / 0 / 1（复制无损） |
| 抽 common 后 | 198 / 0 / 0 / 1（抽取无损） |
| 全量构建 | 6 模块 BUILD SUCCESS |
| 依赖审计 | gateway 无 `spring-webmvc` / `tomcat-embed-core` / `jakarta.servlet` |
| 建库 | `link_platform` 6 张空表 |

> 口径说明：基线是 **1 个设计性跳过**（`IdGeneratorBenchmarkTest`，带 `@EnabledIfSystemProperty(shortlink.benchmark=true)`），不是"全绿无跳过"。

## 6. 本阶段踩的坑

1. `GlobalExceptionHandler` 抽取后编译失败：`MethodArgumentNotValidException` 继承 `spring-context` 的 `BindException`（`spring-web` 不传递），`@Slf4j` 需要 `slf4j-api` → common 补这两个依赖
2. 依赖审计中 `tomcat-embed-el` 是 Spring Cloud Gateway 自带的 EL 库（非容器），红线是 `tomcat-embed-core` / `spring-webmvc`
