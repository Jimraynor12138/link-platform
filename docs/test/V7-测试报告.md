## 4. 结论与限制

**结论**

1. 网关多一跳：P50 **+1.19ms**、P95 **+1.71ms**，同并发 QPS **-27%**。
2. 异步化：QPS **1236 → 2134（+73%）**，P50 **7.30 → 4.36ms**。
3. 本机单节点小消息场景：Rabbit（2134 QPS）优于 Kafka（1450 QPS）；但 Kafka 消费端严重落后（lag 17,871），说明**单消费者 + 逐条写 Redis** 是瓶颈，需要调大消费并发。

**限制（如实标注，不回避）**

- 压测客户端是单进程 Node，**c=50 时客户端先饱和**，因此结论只取 c=10 的相对对比，绝对值不代表服务上限
- 未接 JVM/GC/DB 指标，只有客户端观测
- 单机 Docker，资源与生产不同
- **浏览器冒烟未执行**：本轮用 `curl` 验证了 Nginx 静态页与 `/auth` 反代，未做真实点击（Playwright/agent-browser 在本环境下安装不稳定，P6-1 继续挂账）
