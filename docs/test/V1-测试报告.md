# V1（P1）测试报告

> 版本：V1（P1 link-auth 认证链路与租户模型）｜ 日期：2026-10-16
> 环境：JDK 17 · Maven 3.9.5 · Windows cmd · MySQL 8（`link_platform`）· Redis（db 1）

---

## 1. 测试目标

1. **规范化无损**：包名与配置前缀改名后，core 的 198 个单测必须与 P0 基线一字不差。
2. **认证链路可用**：登录 / 刷新轮换 / 登出撤销三条链路，以及禁用拦截与越权防护。
3. **真实可跑**：起服务 + 真实 MySQL/Redis 走通端到端。

**link-auth 的 4 组用例（对应方案要求）**

| 组 | 测试类 | 用例数 | 覆盖内容 |
|---|---|---|---|
| 组1 登录 | `AuthLoginTest` | 3 | 登录成功返回双令牌并写 Redis；密码错误 → `A0401`；账号禁用 → `A0403` |
| 组2 刷新轮换 | `AuthRefreshTokenTest` | 4 | 成功轮换并覆盖 Redis；旧令牌重放被拒；类型不对直接拒（不碰 Redis）；用户不存在被拒 |
| 组3 禁用与黑名单 | `AuthDisabledAndBlacklistTest` | 8 | 禁用用户无法续期；登出写失效名单 + 删 Refresh；失效名单 key/TTL/跳过已过期；过滤器对黑名单令牌不认证、对有效令牌认证 |
| 组4 租户越权 | `AuthTenantIsolationTest` | 3 | 从令牌注入租户标识并在 finally 清理（含下游抛异常场景）；未认证不注入 |
| 附加 | `JwtTokenServiceTest` | 6 | `tenantId`/`jti` 在签发与解析两端一致；双令牌类型互斥；jti 唯一；篡改令牌被拒；请求头解析；**弱密钥被拒** |
| 附加 | `AuthPropertiesTest` | 4 | 密钥启动期校验：未配置 / 占位符未解析 / 强度不足 → 拒绝启动；合规密钥通过 |

**复审修复验证（S1）**

| 场景 | 期望 | 实际 |
|---|---|---|
| 非 dev 且不提供 `LINK_AUTH_JWT_SECRET` | 拒绝启动 | ✅ 启动失败（不会用可预测密钥签发令牌） |
| dev profile（密钥来自 `application-dev.yml`） | 正常启动并登录 | ✅ `login code=0` |

**测试风格**：全部为 Mockito 纯单测（`@ExtendWith(MockitoExtension.class)`）或直接构造被测对象，
**不加载 Spring 上下文、不依赖 MySQL/Redis，第 1~2 节可在离线环境全绿** —— 与 core 保持一致。

## 3. 端到端冒烟（真实服务 + 真实中间件）

命令方式：打包 `link-auth` 可执行 jar → 启动（`--spring.profiles.active=dev`）→ 走 HTTP 链路。

| # | 步骤 | 期望 | 实际 | 判定 |
|---|---|---|---|---|
| 1 | 登录 `tenantadmin/123456` | 成功，租户 1 | `code=0, tenant=1` | ✅ |
| 2 | 带令牌访问 `/auth/me` | 成功，租户上下文正确 | `code=0, tenant=1, roles=TENANT_ADMIN` | ✅ |
| 3 | 无令牌访问 `/auth/me` | 401 | `401` | ✅ |
| 4 | 只读账号访问需 `user:manage` 的接口 | 403 | `403` | ✅ |
| 5 | 刷新令牌 | 成功 | `code=0` | ✅ |
| 6 | 旧刷新令牌重放 | 被拒 | `A0401` | ✅ |
| 7 | 登出 | 成功 | `code=0` | ✅ |
| 8 | 登出后旧 Access Token 再访问 | 401 | `401` | ✅ |
| 9 | 禁用账号登录 | 被拒 | `A0403` | ✅ |

**9/9 通过**。

> 第 4 步首轮为失败（返回"成功"），定位为"`@PreAuthorize` 的拒绝异常被全局兜底处理器吞成 200"的安全漏洞，
> 修复后复测通过。详见 `docs/devlog/V1-P1-*.md` 踩坑 1。

## 5. 结论

- ✅ **规范化无损**：包名/前缀改名后 core 仍是 `198/0/0/1`
- ✅ **认证链路可用**：登录 / 刷新轮换 / 登出撤销 / 禁用拦截 / 越权防护，单元与端到端双重验证
- ✅ **测出真问题**：E2E 暴露了 1 个鉴权失效漏洞与 1 个刷新白名单缺陷，均已修复
- ⚠️ 已知遗留：core 的 Redis key 前缀硬编码（`short-link:*`）、`LinkCoreProperties.domain` 默认值未同步、用户名全局唯一 —— 见 `docs/devlog/V1-P1-*.md` 第 7 节与代码审查
